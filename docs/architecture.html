Architecture Overview · v1

智能体干活，人类只审批

织序是纺织贸易的智能体原生业务操作系统。架构的核心不是「人操作系统」，而是 确定性内核（唯一写入口） + 工具层（智能体唯一入口） + 审批窗口（人类唯一决策入口）。智能体的产出永远是草稿与建议，账本只在人类批准后由内核写入，并与审计同事务落库。

9apps · 多端应用
7packages · 共享契约与 UI
1模块化单体后端（NestJS）
4条不可违反的架构铁律

02

端与职责

一个产品一个仓库。每个端只承担一件事，共享 packages/core 的数据与状态逻辑、packages/schema 的契约。

apps/web · Next.js 15

租户工作台

三个业务窗口 + 一个管理面：工作台（⌘1）、审批（⌘2）、全景只读（⌘3）、组织设置（⌘,）。打印是全局抽屉，不是第四窗口。

  • 只调只读目录、工具、/api/approvals/decide
  • OIDC token 只存 httpOnly Cookie
  • 前端不读 token，不落 localStorage
apps/mobile · Taro

移动端

一套 React 代码输出 H5/PWA，后续可编译小程序与 RN App。底部五入口：今日 / 审批 / 相机 / 客户 / 更多。

  • 业务逻辑 100% 复用 packages/core
  • 离线队列落 IndexedDB，恢复后按序提交
  • 冲突策略：服务端版本 + 人工确认
apps/quote · Next.js 15

客户报价页

公开路由组 /s/[token]，SSR + 无鉴权 Cookie + 独立部署，客户面与租户面物理隔离。

  • 只返回客户视图字段，绝不返回成本 / 毛利 / 内部备注
  • 支持接受意向、留言提问、PDF 下载事件
  • 撤回后立即 410
apps/admin + apps/platform-api

平台控制台

租户总览、订阅账单、用量、套餐、LLM 设置、身份、配置中心、支持与平台审计。独立应用、独立部署、强制 MFA。

  • 只连控制面数据（platform_* / plans / subscriptions）
  • 默认看不到租户业务数据
  • Break-glass：租户同意 + 双人复核 + 限时只读 + 全程审计
apps/cli + skills/weave-order

CLI / Agent 接入

weave 命令：设备码登录、凭据管理、业务工具、把 skill 安装到 codex 等 agent 环境。

  • 用 PAT 而不是 OIDC 会话
  • PAT 绑定 membership，仍走同一租户与 RLS
  • 审批需人类显式签发 approve 作用域
apps/print-agent · Tauri 2

打印代理

本地常驻、托盘、WSS 出站长连接、不开启入站端口。A4 PDF 走系统打印，标签走 RAW TCP 9100。

  • 专用 token：只能打印，不能读业务数据
  • 本地 spool ≤ 24h，idempotency_key 去重
  • 签名自动更新，灰度可回滚
03

一次业务动作的主链路

以「寄样单 / 报价」为例：智能体把事做到只剩一个决定，人类在审批窗口按下批准，状态才流转。

01 · HUMAN

派发意图

工作台选上下文（客户 / 样品），输入意图，或粘贴客户原话。

Intent Bar
02 · AGENT

编排 + 调工具

LangGraph 状态机在 PostgreSQL 上打检查点，节点只调用 tools，输入输出全部 Zod 校验。

T-001…T-006
03 · KERNEL

计算并落草稿

金额用整数「分」+ BigInt 计算，成本底线、定价继承、审批阈值都在内核判定，强制产出 DRAFT。

DRAFT / 建议
04 · HUMAN

审批决策

审批窗口看得到出处、diff、草稿态；批准或驳回，可带分诊备注。这是唯一状态流转入口。

POST /api/approvals/decide
05 · KERNEL

生效 + 留痕

内核校验 actor.type === "HUMAN"，同事务改状态并写审计；审计表由触发器禁止改写。

SENT / CONFIRMED + audit_log

智能体的完整旅程（寄样跟进）

建寄样单 (T-005) → 追踪物流 → 生成跟进建议
   → 等待客户回复 (interrupt · checkpoint)
   → 识别回复 → 客户询价？
        ├─ 是 → 生成报价草稿 (T-004, DRAFT) → DONE
        └─ 否 → DONE

进程 A 中断并打印 checkpoint id；全新 Node 进程 B 从同一 thread 恢复，注入回复继续跑。物流 / LLM / 回复来源都是 provider 接口，默认本地确定性实现。

失败语义是封闭可判别联合

业务失败仍返回 { ok: false, error }，HTTP 状态按 code / reason 映射为 400 / 403 / 404 / 409 / 422 / 502。

  • PERMISSION_DENIED — 智能体试图确认草稿
  • PRICE_BELOW_COST_FLOOR — 报价击穿成本底线
  • NO_TRACKING_NUMBER — 缺运单号，零副作用拒绝
  • BATCH_REJECTED / WRITE_FAILED — 导入整批回滚
  • KERNEL_REJECTED — 数量/金额超界

数据模型与隔离

共享库 + RLS 起步，可按租户单向升级到 schema-per-tenant / 独立库。每张业务表带 tenant_id，连接先 SET LOCAL app.tenant_id。

交易与账本

quotesquote_sharesordersinboundreceivablesreceivable_paymentsrevisionsdecision_deltasintents

审计与凭据

audit_logauth (tokens)tenants / membershipsaudit_export_jobs

关键约定

  • 金额：一律整数「分」，PG bigint，行金额用 BigInt 计算再一次 half-up；契约层以 Number.MAX_SAFE_INTEGER 兜底。
  • 数量：千分之一单位整数，乘法走 BigInt，超界显式 KERNEL_REJECTED。
  • 输入契约：全部 .strict()，智能体不能夹带 status、version 等账本字段。
  • 审计不可改：业务写入与审计写入同一事务；audit_log 由数据库触发器禁止 UPDATE / DELETE。
  • 数据范围：owner_id + 角色 dataScope（OWN / TEAM / ALL），生产缺令牌 401，缺角色 fail-closed。
  • 向量：vector(1024) + HNSW；local-stub 走 real[] 兼容，零外部 key 可演示。
  • 控制面分离：platform_* / plans / subscriptions / usage_* / invoices 在独立库，平台侧只看聚合。

08

架构铁律

这四条不是建议，是代码与数据库里可被测试验证的约束。

1
确定性内核与智能体外壳分离

智能体永远不直接修改库存、应收、合同状态。只有 src/kernel 能写业务表；工具层只拿到 Kernel 对象，拿不到 Db。

2
智能体输出一律是草稿 / 建议

内核 createDraft 强制 DRAFT；confirm* / reject* 校验 actor.type === "HUMAN"，人类批准后才生效。

3
每个业务能力以工具形式暴露

工具输入输出严格 Schema 校验；智能体不「打开页面」，只调用工具。审批决策只有 /api/approvals/decide 一个入口。

4
人类界面只有三个窗口

任务派发（Intent Bar）、审批与异常分诊（Review Queue）、业务全景只读（Read-Only Panorama）。不做第二个写入口。

铁律在代码里的可验证落点

  • eslint.config.mjs 的 no-restricted-imports：agent 禁止 import kernel / drizzle-orm / pg / @weave-order/db；tools / approval / import / http 禁止直连数据库。
  • apps/api/test/boundary.test.ts：常驻回归测试锁定目录边界，改配置会被测出来；http 层例外仅限两个组合根文件。
  • apps/api/test/schema-parity.test.ts：数据库枚举与契约枚举逐项比对，契约只有一处定义。
  • apps/api/test/import.integration.test.ts：整批原子导入——任一坏行整批不提交，失败零脏数据。
  • apps/api/test/track-a.integration.test.ts / track-a.e2e.test.ts：报价全链路与审计留痕。
