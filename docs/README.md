> **任何 agent / 新人开工前先读这一页。** 它给出"这个项目的目标是什么、有哪些端、哪些规矩不能动、现状到底有什么"的跳转表，3 分钟读完再动手。

## 一分钟读懂这个项目

**织序 WeaveOrder** —— 纺织贸易公司的 agent-native 业务操作系统。

一句话：**AI 干完整的活（查历史、算价、写单、跟进），人只在需要签字的地方出现。**

- 输入是「客户的一句话」，输出是「客户收到的东西」，中间那段以前是人的手，现在是智能体。
- 账本（价格、单据、应收）由**确定性内核**唯一写入，智能体永远够不到。
- 智能体的一切产出都是**草稿**，生效必须有人类的具名动作。
- 界面只有三个**决策面**：派发 / 审批 / 全景。功能增长时界面不增长——这是这套形态的经济性根基。

## 四条铁律（不可违反）

1. **确定性内核与智能体外壳分离** —— 智能体永不改账本，一切涉及账本/资金的动作经工具进内核并写审计。
2. **智能体输出一律是草稿 / 建议** —— 人类确认后才生效。
3. **每个业务能力以 Tool 形式暴露** —— agent 不"打开页面"，只调工具。
4. **人类只有三个决策面** —— 派发 / 审批 / 全景；不是"只有三个页面"，也不是"只有三个端"。

落点与可验证方式见根 `README.md` 的「铁律在代码与数据库里的落点」表。

## 开工前的三个自检问题

1. 这个需求属于哪个**决策面**？三个都不是 → 它大概不该做成界面。
2. 它落在哪个**端**？已经有权威端了吗？（见 `product-vision.md` §3.5）有就别在第二个端再做一遍。
3. 它违反哪条 **INV**？一条都不违反 → 它可能只是实现细节，不必讨论；违反了 → 先改文档、写清代价，再动代码。
