# 端到端验收：自动化覆盖 + 真机 10 分钟清单（WAN-128）

> 目标：把「机器能替的」全部自动化，人只做机器替不了的三件事 ——
> 真机相机权限、按一次真实快门、判断「看起来对不对」。

## 一条命令

```bash
pnpm e2e
```

它会按顺序做：

1. 检查 / 启动本地 MinIO（`scripts/dev-storage-up.sh`；也可 `E2E_SKIP_STORAGE=1` 用外部 S3）
2. `pnpm db:migrate`（幂等）
3. 构建 web 与移动端 Taro H5（**关 mock**、API 指向 E2E 专用端口）
4. 安装/确认 Playwright Chromium
5. 用独立端口拉起 API `:3100`、Web `:3101`、H5 `:3102`，跑全部 spec

产物：

| 内容                  | 路径                                                                      |
| --------------------- | ------------------------------------------------------------------------- |
| 3 档视口 + 移动端截图 | `e2e/.artifacts/screenshots/`                                             |
| HTML 报告             | `e2e/.artifacts/report/index.html`                                        |
| 失败 trace            | `e2e/.artifacts/test-results/`（`pnpm exec playwright show-trace <zip>`） |

常用开关：`E2E_SKIP_BUILD=1`（只改 spec 时）、`E2E_SKIP_MIGRATE=1`、
`E2E_SKIP_BROWSER_INSTALL=1`、`E2E_REUSE_SERVERS=1`（复用已起的 3100~3102）。

## 自动化断言清单

| Spec                                             | 覆盖                       | 关键断言                                                                                                                                                                            |
| ------------------------------------------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `desktop/gallery-layout.spec.ts` × 1280/1440/375 | S2 验收 1/8                | 首行卡片顶边对齐、宽度一致、列数 = 5/5/2，其余行宽度与间距一致；`document.scrollingElement.scrollWidth <= clientWidth`；首屏所有图片请求都带 `?w=320`（没有原图 key）               |
| `desktop/sample-detail.spec.ts`                  | S2 验收 2/3                | 大图顺序 = 服务端 `images`（sortOrder）顺序（种子故意「先传 sortOrder=2、后传 1」）；规格表逐项可见；OWNER 看到成本底线 `¥12.00`，SALES 的 API 返回 `costFloor=null` 且页面显示 `—` |
| `desktop/image-search.spec.ts`                   | S4 契约                    | `setInputFiles` 上传查询图 → presign/PUT → T-001；top-5；每条 `matchedImageUrl` 非空且缩略图真实解码；local-stub 时界面标注「演示模式」                                             |
| `mobile/mobile-h5.spec.ts`                       | S4 验收 7 / 移动端关键路径 | Taro 构建产物（无 mock）：拍照建样品 → 图墙 → 详情 → 拍照找样；上传走 Taro `chooseImage` 同一条 change 链路；候选带命中缩略图；无横向滚动                                           |

没有任何 `test.skip`。共享数据库里可能存在其它测试数据，所以视图断言用
「E2E- 前缀搜索」把范围收敛到本次种子。

### 数据种子（幂等）

`e2e/support/seed.ts` 只通过 HTTP API 写数据（顺带验证 presign → PUT → confirm → 后台索引）：

- 5 个样品共用同一张 `e2e/fixtures/fabric-primary.jpg`：即使 `local-stub` 是哈希向量，
  同图余弦也是 1.0，「top-5 且每条带 matchedImageUrl」在零外部 key 下也能成立；
- 1 个双图样品（`sortOrder` 与上传顺序相反）用于轮播顺序断言；
- code 由 fixture 内容哈希派生，重复跑不会制造新样品。

### 真实多模态模型（可选）

默认 `IMAGE_EMBEDDING_PROVIDER=local-stub`：链路真、分数无语义，界面显示「演示模式」。
要用真实模型跑同一套断言：

```bash
IMAGE_EMBEDDING_PROVIDER=dashscope-qwen3-vl \
IMAGE_EMBEDDING_API_KEY=sk-... \
IMAGE_EMBEDDING_MAX_EDGE=512 \
pnpm e2e
```

此时 spec 里 `semantic=true` 分支会断言「不出现演示模式」；top-5 断言不变
（同图仍是最高分）。不需要改任何测试代码。

## 真机 10 分钟验收清单

前置：`pnpm e2e` 已通过；手机与电脑同一 Wi-Fi，浏览器打开 `http://<电脑局域网 IP>:3102`
（正式环境换域名）。每步「不对先查什么」按顺序看，不要跳。

| #   | 做什么                                          | 预期看到什么                                                     | 不对时先查什么                                                |
| --- | ----------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | 首次进入「相机」→「打开相机」                   | 系统弹出相机/选择图片权限                                        | 是不是浏览器禁用了相机；iOS 需 Safari 或已安装 PWA            |
| 2   | 允许权限后真实拍一张布样                        | 预览图方向正确、长边 ≤1600、体积 ≤1MB                            | 图片横竖颠倒 → 查手机 EXIF 方向；超 1MB → 压缩是否执行        |
| 3   | 填品名「真机验收 xx」→「保存到样品库」          | 提示「已建样品」，图墙出现同名卡片                               | 网络是否可达 API；失败文案是否指出原因（不允许静默失败）      |
| 4   | 打开「更多 → 样品库」看整面墙                   | 2 列、无横向滚动；缩略图清晰不变形；无「假色卡」                 | 出现待补图 → 看图片是否真的挂上；模糊 → 是否请求了 `?w=320`   |
| 5   | 点刚建的样品看详情                              | 大图与图墙一致；编码/成分/克重/状态可读                          | 大图裂 → 对象存储是否匿名可读/CDN 域名；顺序错 → 看 sortOrder |
| 6   | 换业务员账号打开同一个样品                      | 看不到「成本底线」（显示 `—`）                                   | 仍能看到 → 角色裁剪在服务端是否生效，别改前端                 |
| 7   | 回「相机」→「找样」→「从相册」选第 2 步那张原图 | 候选 ≤5 条，每条有命中缩略图；第一候选就是本样品                 | 0 条 → 看是否仍有图在索引（提示会写「还有 N 张索引中」）      |
| 8   | 观察第 7 步的提示条                             | 显示「演示模式」就说明当前是哈希向量；配了真实模型应显示正常候选 | 文案缺失 → 前端是否把 `semantic=false` 当成了真图搜图         |
| 9   | 关 Wi-Fi 后重复第 2~3 步                        | 明确提示「已存本地/需要联网」，不丢照片                          | 白屏/静默成功 → 离线分支被绕过                                |
| 10  | 恢复网络后回页面                                | 队列自动补传，或给出可理解的失败原因                             | 不补传 → 看「更多 → 离线队列」明细                            |

### 只有人能判断的三件事

1. **颜色是否接近实物**（屏幕色差，任何断言都替不了）；
2. **模糊/畸变是否可接受**（缩略图尺寸对，但观感可能仍差）；
3. **提示文案是否让人看得懂**（尤其是权限被拒、离线、索引中三种状态）。

## 本次自动化顺带发现并修复的真实缺陷

| 缺陷                                                                     | 影响                                                                                                                       | 修复                                                     |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `apps/api/src/main.ts` 缺 `await app.listen()`（WAN-119 收拾 S4 时误删） | 进程打印「API → http://localhost:3000」后以 0 退出，**真实后端根本无法启动**；CI 只有直接 import 模块的 vitest，所以一直绿 | 单独 commit 恢复监听；E2E 的第一步就会拦住同类回归       |
| `/api/media/presign` 不返回 `publicUrl`                                  | 移动端 `PresignResultSchema` 要求该字段，真实后端拍照找样在上传后必然解析失败                                              | presign 返回 CDN/签名读地址；core 契约同步               |
| 375 视口横向滚动（441px）                                                | 桌面工作台在窄屏溢出，S2 验收 8 不成立                                                                                     | 关闭的打印抽屉不再留在 DOM；顶栏在 <640 隐藏桌面专属入口 |
